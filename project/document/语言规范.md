# Well 语言规范（`.we`）

> **基线**：2026-10-23（审计修复后），**184 个 `.we` 端到端用例 + 18 个 C 测试**全部通过（`python tools\verify.py`，Windows + TinyCC ≈160s）；Linux CI（gcc -O2）全量回归通过；`wellc check` 支持人类可读与 `--json` 两种输出（语义错误可多条、带 `FILE:LINE:COL`）。
> **说明**：本文件是现行语言规范，替代早期草案 `语言规范.txt`（其中的 `char/short`、`funcs` 关键字、`super.run()`、`Model.findByOid` 的旧语义、独立进程垃圾桶等均未实现或已废弃）。本版按 2026-10-23 重做版《核心代码审计》与 110 条修复后的实现重写类型/声明/诊断等章节；实现有冲突时以 `project/compiler` 源码与测试为准。

## 1. 概述

- **名字 / 扩展名**：Well，源码文件 `.we`。
- **编译方式**：Python 前端编译为 C99，再由 C 编译器编译为原生可执行文件：

  ```text
  .we → lexer → parser → checker → codegen → build/<stem>_<hash8>.c
      → TinyCC（默认，Windows）或 gcc/clang（POSIX 默认，gcc/clang 自动 -O2 -fwrapv）
      → 可执行文件（链接 runtime/core + 用到的 modules/http|ws|mysql）
  ```

  `build/` 被所有源文件共享，生成 C/exe 的名字带绝对路径的短 hash（`<stem>_<hash8>`），不同目录的同名 `main.we` 不会互相覆盖；`-o` 可显式指定输出。

- **运行模型**：oid actor。
  - 每个 oid 一条 FIFO 队列，同一 oid 同时最多一个 runner，不同 oid 可并行；
  - `handler` 是执行逻辑的基本单位，run-to-completion（没有 await/yield）；
  - `controller.run()` 在事件循环之前执行（装配期，`ctx.oid = 0`）；
  - 长期数据放 `Model`/`Cache`，`controller`/`handler` 不保存字段（无状态）；
  - 事件 `emit` 异步派发，按目标 oid 排队。

## 2. 关键词

### 2.1 保留字（lexer `KEYWORDS`）

| 类别 | 保留字 |
| --- | --- |
| 文件/声明 | `module` `import` `entry` `const` `enum` `struct` `event` `controller` `handler` `func` `namespace` `static` `extends` |
| 语句/控制 | `if` `else` `while` `for` `switch` `return` `break` `continue` |
| 变量/构造 | `var` `new` |
| 字面量 | `true` `false` `null` |
| 类型 | `void` `bool` `int` `long` `float` `double` `String` |

### 2.2 上下文词（词法上是普通标识符，但语法中有固定含义）

| 词 | 语境 | 说明 |
| --- | --- | --- |
| `case` / `default` | `switch` | case 标签 |
| `of` / `in` | `for` | `for (var v of arr)` 取值；`for (var k in map)` 取键（**必须带 `var`**） |
| `ALL` | `on/once/off` | 通配所有 channel 的订阅 |
| `Bytes` `Array` `Map` `Linked` | 类型位置 | 内建类型名（按标识符解析，不要重定义） |

### 2.3 内建名（普通标识符，但语言/运行时保留）

- 根类型：`Vo`、`Event`、`Controller`、`Handler`；struct/event 的根 `extends` 可省略，controller/handler **不支持** `extends`。这四个根类型**只能出现在 `extends` 基类位置**（以及 `Model.get/peek/findByOid(Vo, oid)` 白名单），不能用作字段/参数/变量类型。
- 内置对象：`Model`、`Cache`、`Json`、`IdUtil`、`Timer`、`File`、`Host`、`Http`、`Ws`、`Mysql`、`String`、`Bytes`、`Array`、`Map`、`Linked`。
- 内置函数：`print`、`on`、`once`、`off`、`emit`、`start`、`stop`。
- **这些名字不能用作自己的声明名**，否则与内建 API 冲突（语义解析优先匹配内建名）。
- 与 C 关键字/libc/运行时符号同名的 Well 名字（如 `register`、`goto`、`main`、`printf`、`well_new`、`WellCtx`）**可以正常声明和使用**：codegen 会给生成的 C 符号加类别前缀（见 §5.2），Well 原名保留在元数据/JSON/诊断中。

### 2.4 运算符与标点

```text
+  -  *  /  %  ==  !=  <  <=  >  >=  &&  ||  !  ~  ??  ? :
=  (  )  [  ]  {  }  ;  ,  .  :
```

- 已实现：算术、比较、逻辑、三目 `? :`、一元 `! - + ~`。
- 空值合并 `??` **暂不实现**：语法保留，checker 明确报 `operator ?? is not implemented; write x == null ? y : x`，请改写为 `x == null ? y : x`。
- 复合赋值：`a += b` / `a -= b`（等价 `a = a + b` / `a = a - b`，支持变量/字段/下标目标；**目标表达式只求值一次**，例如 `a[i()] += 1` 只调用一次 `i()`）。
- `->` 是**保留符号**（预留给 lambda/管道，暂未实现；使用会报编译错误）；成员访问只用 `a.b`。
- 整数 `/`、`%` 是 checked 的：除数为 0 → panic（带 `file:line`）；常量除零/溢出是编译错误。

### 2.5 标识符、注释、字面量

- 标识符：字母/下划线开头，后续字母/数字/下划线（词法器按 Unicode 字母判断，中文等非 ASCII 标识符可编译；实际项目建议 ASCII）。C 关键字/标准库/运行时符号名可安全使用（codegen 自动加前缀）。
- 注释：`// 行注释`、`/* 块注释 */`（块注释不嵌套）。
- 整数字面量：十进制（允许前导 0，`08` = 8）、`0x`/`0X` 十六进制（**`0x` 后必须至少一位十六进制数字**，否则词法错误）；超过 int32 的自动按 `long`。
- 浮点：`1.5`、`1e3`、`.5`；指数符号后**必须有数字**；非有限结果（如 `1e999`）是词法错误；`float`/`double` 都映射 C `double`。
- 字符串：双引号；转义只支持 `\n \t \r \\ \" \0`，**未知转义（如 `\q`）是词法错误**；字符串内允许裸换行（行号/列号会正确递增）。
- `String` 的 `length`/下标/切片/`indexOf` **按字节**；UTF-8 码点用 `codePointAt`/`fromCodePoint`。

## 3. 语法规则

### 3.1 文件结构

```we
module demo.app;            // 仅声明，解析后忽略（不参与查找、不是命名空间）

import "lib/util.we";       // 相对路径；也可省略 .we：import "lib/util"
import lib.util;            // 点路径：lib/util.we → lib/util/index.we → lib/util.we 的同名回退

entry MainController;       // 入口 controller；只有被编译的根文件里的 entry 有效

// ……声明（struct/event/enum/const/controller/handler/func/namespace/static）
```

- `import` 语义是**声明合并**：被导入文件的顶层声明全部进入同一个程序；import 可递归（import 的文件再 import，同一文件只解析/合并一次，循环 import 有去重）。
- 所有声明共享**一个全局命名空间**：同一文件内重复声明是编译错误；**跨文件同名声明（任意类别：struct/func/const/namespace/...）同样是编译错误**，错误信息包含首次定义文件。
- 无法解析的 import 只是 **warning**（`check` 的 JSON 里 `severity=warning, code=import`；`build` 也打印 warning 到 stderr），不阻止编译；真正引用缺失声明时才会报未定义。
- `entry` 必须在**被编译的根文件**中；导入文件里的 `entry` 会被忽略。
- 没有独立的包/命名空间隔离，`module` 名不参与解析。

### 3.2 类型

| 类型 | C/运行时表示 | 说明 |
| --- | --- | --- |
| `bool` | `int` | `true/false`；与 `int` 可互相赋值（C 表示相同） |
| `int` | `int`（32 位） | 超出 int32 的字面量按 `long` |
| `long` | `long long`（64 位） | |
| `float` / `double` | `double` | 两个名字等价 |
| `String` | `WellString*` | 不可变、引用类型、可 null；长度/下标按字节 |
| `Bytes` | `WellBytes*` | 可变字节缓冲、引用类型 |
| `Array<T>` / `Map<T>` / `Linked<T>` | `WellArray*` / `WellMap*` / `WellLinked*` | 同质容器；Map 键为 `String`，保留插入序 |
| `struct` / `event` | `T*` | 引用类型、有 oid |
| `null` | `void*` | 不是可声明类型，只能作为引用类型的值 |
| `void` | — | 只能作返回类型，不能作参数/字段/变量/容器元素类型 |

**类型规则（checker 强制，2026-10-23 修复后）**：

- 赋值/初始化/实参/返回值/字段/容器元素统一走兼容性检查：显式注解 `var x: T = e` 的 `T` 必须与 `e` 类型兼容；函数实参逐个校验；`return` 校验；struct/static 字段默认值校验。
- **数值只允许 widening**：`bool → int → long → double`（float/double 都视为 double）；反向窄化（`long → int`、`double → int/long`）是编译错误，需要改用匹配类型或先确认范围（语言不提供显式 cast）。注意：**bool 只能与 int 互赋，不参与算术/大小比较/取模**（仅可用于条件与 `&&/||/!`）。
- `null` 只能赋给引用类型（`String`/`Bytes`/容器/struct/event）；赋给 `int`/`bool`/数值/`void` 是编译错误。
- `void` 只能作返回类型（含省略）：`func f(a: void)`、`var x: void`、`var x = f()`（f 为 void）都会报错；void 表达式不能用于 print/运算/比较/条件/实参。
- 引用类型之间**不隐式转换**：`Derived` event/struct 不能赋给 `Base` 变量（只支持字段展平，没有多态/子类型赋值）。
- 可空类型标注 `T?` **目前只是语法保留**：parser 接受，但 checker 忽略 nullable（等同 `T`），不提供 null 收窄/空安全；不要依赖。
- 没有 `char`/`short`；整数只有 `int`/`long`；**没有 enum 类型**：`enum` 只是 int/String 常量集合，字段用 `int`/`String` 存值。
- 所有引用类型默认 `null`；struct/event 的 `String` 字段默认 `""`。

### 3.3 声明

#### struct / event

```we
struct BaseVo {
    id: long;
}

struct UserVo extends BaseVo {   // 单继承，仅字段展平
    name: String;
    tags: Array<String>;
}

event BasePingEvent {
    n: int;
}

event PingEvent extends BasePingEvent {
    msg: String;
}
```

- 字段语法：`name: Type [= 默认值];`；struct 没有方法，只有字段，没有多态/虚调用。
- **字段默认值受限**（与 static 字段规则一致）：只允许字面量、const、枚举成员、容器字面量（`[..]`/`{..}`，元素/值类型需匹配）以及 `new Bytes()` / `new Array<T>()` / `new Map<T>()`；函数调用、`Host.*`、`Json.*`、`new <struct/event>` 等任意表达式都报 `default value must be a compile-time literal/const/container literal`。
- 构造：`new UserVo()`（oid = ctx.oid）；`new PingEvent(targetOid)`（event oid = targetOid，传 0 表示 emit 时生成新 oid）；字段初始化：`new PingEvent(0) { n: 1, msg: "x" }`。
- event 构造完成后**冻结**（字段只读）：运行期写 event 字段会 panic `write to frozen event`（带 file:line）；event 类型本身即事件身份（`type_id`）。
- `extends Vo` / `extends Event` 可省略；未知基类、循环继承、重复字段是编译错误。`Derived` 不能赋给 `Base`（无子类型赋值）。

#### const / enum

```we
const MAX: int = 10;
const NAME: String = "well";
const SUM: int = 1 + 2;        // 常量算术可以

enum Status { IDLE; RUNNING; DONE; }          // 0,1,2
enum Color { RED = "red"; BLUE = "blue"; }    // String 枚举
enum Code: int { OK = 0; ERR = 1; }           // 可选的底层类型标注（int/long/String）

print(Status.fromInt(1));     // RUNNING（未知 -> 0）
print(Status.toString(1));    // RUNNING（未知 -> ""）
print(Color.toString("red")); // RED
```

- `const` 必须是**编译期常量**：字面量、枚举成员、另一个 `const`、以及它们的数值运算；`new`、函数调用、`Host.nowMs()`、String 拼接/容器都会被拒绝（`const 生成 C 宏并按引用点展开`）。
- enum 成员用 `;` 分隔；int 枚举可显式赋值（只能是非负十进制/`0x` 字面量，负数语法不支持）或自增；重复 int 值报错。
- 可选底层类型 `enum E: int|long|String`：声明后 checker 校验成员值一致（`enum Bad: String { A = 1 }` 报错）；int/long 枚举行为等价。
- String 枚举成员可以像普通 String 值使用（比较/拼接/作 `switch` case），运行时生成 `well_string_lit(...)`。
- enum 不是类型：`var s: Status` 不合法，用 `int`/`String` 存枚举值；`E.fromInt` 仅 int 枚举，`E.toString` 支持 int/String 枚举。

#### controller

```we
controller MainController {
    run() {
        on(PingHandler);                       // 推荐：事件类型从 handler 参数推断
        Http.route("/hello", "GET", HelloHandler);
        Http.listen(8080);
    }
}
```

- 单例；`run()` 在事件循环前执行，`ctx.oid = 0`（装配期 oid）。
- **controller 只能定义 `run()`**：定义其它方法报 `unsupported method ... (a controller only supports run())`；重复 `run` 报 duplicate method；未定义 `run()` 报错。
- 在 `run()` 中可注册路由/订阅、初始化 static、创建 **oid=0 系统级只读数据**。
- `start(C)` 幂等启动子 controller；`stop(C)` 注销该 controller 的订阅并允许重启。
- **controller/handler 不支持继承**：语法已移除，写 `extends` 会直接编译错误。

#### handler

```we
handler PingHandler {
    onEvent(e: PingEvent) {
        print(e.n);
    }
}
```

- 执行事件逻辑的基本单位；方法名接受 `onEvent` / `handle` / `on` / `handler`，且**必须且只能定义一个**（定义多个报编译错误 `must define exactly one event method`；定义非事件方法报 `unsupported method`）。
- 参数**必须是一个具体的 event 类型**（不能是根类型 `Event`、不能是 struct）；handler 没有字段（无状态）。
- `on(H)` 时事件类型从 `onEvent(e: T)` 推断。
- handler 内定义非事件方法会报 `unsupported method`；重复同名方法报 duplicate method。

#### func / namespace / static

```we
func add(a: int, b: int): int { return a + b; }

namespace Math {
    max(a: int, b: int): int { if (a > b) { return a; } return b; }
}

static AppConfig {
    limit: int = 10;
    title: String = "svc";
    arr: Array<int> = [1, 2, 3];

    bump(): int {
        AppConfig.limit = AppConfig.limit + 1;   // static 方法内字段要写 StaticName.field；仅启动期可写
        return AppConfig.limit;
    }
}
```

- `func` / namespace 函数 / static 方法：参数类型、返回类型、实参类型、`return` 路径都经过 checker；参数重名、同作用域变量重名报错（内层块可遮蔽外层）。
- `N.f(...)` 编译期为静态 C 函数，零运行时开销、不占 oid/RC；namespace 里只能放函数（不能放字段）。
- static 不可实例化、不能作为字段/参数/变量类型；字段启动期可写、运行期只读；运行期写/改容器会 panic。
- static 方法内访问字段必须写 `StaticName.field`（裸字段名不是局部变量，会报 undeclared）。
- static 引用字段不能是 event；static 数据永不参与 TTL 回收。
- static 字段默认值与 struct 字段默认值规则相同：字面量/const/枚举成员/容器字面量/`new Bytes|Array|Map`。
- 运行期需要可变状态请用 Model/oid，不要用 static。

### 3.4 语句

```we
var x: int = 1;          // 类型可省略（由初始化表达式推断）；显式注解必须与初始值兼容
x = x + 1;
x += 2;                  // 等价 x = x + 2（目标只求值一次）
x -= 1;                  // 等价 x = x - 1

if (x > 0) { ... } else { ... }   // 条件必须是 bool/int/long
while (x < 10) { x = x + 1; }
for (var i: int = 0; i < 3; i = i + 1) { ... }
for (var v of arr) { ... }   // Array / Linked 元素（必须写 var）
for (var k in map) { ... }   // Map 键（String，必须写 var）

switch (x) {
    case 1: print("one");
    case 2: print("two"); break;     // 无 fallthrough，break 只是提前退出 switch
    default: print("other");
}

return x;
break;
continue;
```

- `var`：显式注解时初始化表达式必须可赋给注解类型；类型不能推断为 `null`/`void`（必须加注解/改正表达式）；同一作用域重复 `var` 同名报错；内层块可以遮蔽外层变量。
- `if` / `while` / `for` 条件必须是 `bool`/`int`/`long`（`true` 真值语义按 C 非零；String/struct/void 条件报错）。
- `for (var v of arr)` / `for (var k in map)` **必须带 `var`**；for-of 支持 Array/Linked，for-in 只支持 Map 键；循环体内 `break`/`continue` 正常。
- `switch` 支持 `int`/`long`/`String`；**无 fallthrough**（每个 case 自动 break）；case 值必须是字面量/const/枚举成员，重复 case（含 const/枚举求值后相同）报错；String 枚举成员可作 case。
- `switch` 计入 breakable：`break` 退出 switch；`continue` 只作用于外层循环；每个 case 的语句块有独立作用域。
- 赋值目标可以是变量、字段、数组/Map 下标（String/Bytes 下标不可赋值，用 `b.set`）；字段/容器写受 oid 检查约束（见 §6.1）。
- 非 void 函数必须**所有路径** return（`if` 两分支、带 default 的 switch 全覆盖）；`while(true)`/`for(;;)` 这类恒不 fallthrough 的循环视为满足（但若循环体内有本层 `break` 则仍要求后续 return）。
- 整数除零/模零 panic；运行期溢出二补码 wrap（见 §6.5）。

### 3.5 表达式

```we
1 + 2 * 3
a == b, a != b, a < b, a <= b, a > b, a >= b
a && b, a || b, !a
cond ? x : y
x ?? fallback              // 空值合并：**暂不实现**，checker 明确报错；请用 x == null ? y : x
"a" + "b"                  // String + String（单次拼接 O(len(a)+len(b))）
arr[i], map["k"], obj.field
new UserVo(), new PingEvent(0) { n: 1 }, new Bytes()
[1, 2, 3], {"k": 1}        // 容器字面量（受限，见下）
```

**运算符类型规则（checker 强制）**：

| 运算 | 允许的操作数 | 结果 |
| --- | --- | --- |
| `==` / `!=` | 两侧同类型、两侧均为数值、或一侧为 `null` 且另一侧为引用类型（`String`/`Bytes`/容器/struct/event；`1 == null` 报错） | `bool`；**String 按内容比较**（codegen 用 `well_string_eq`），struct/event/容器比较引用（指针身份）；`true == false` 合法 |
| `<` `<=` `>` `>=` | **仅数值**（int/long/float/double，可混用；bool 不参与） | `bool`；String 不支持大小比较 |
| `&&` `\|\|` `!` | `bool`/`int`/`long`（按 C 真值语义；`!1` 合法） | `bool` |
| `+ - * /` | **仅数值**（int/long/float/double；bool 不参与算术） | 数值取较宽类型 |
| `+`（String） | **两个 String** | String（拼接） |
| `%` | **仅整数 int/long**（不接受 bool/float/double） | 数值 |
| `- + ~`（一元）、`!` | `- + ~` 数值（`~` 仅 int/long）；`!` 接受 bool/int/long | 同操作数 / `!` 为 bool |
| `?:` | **当前实现不对条件/分支做强校验**（条件不做 bool 要求，两分支类型不强制一致） | 取左分支类型（左为 null 时取右）；建议两分支同型、条件用 bool |

- 容器字面量 `[]`/`{}` 只支持：`var` 初始化、赋值、static/struct 字段默认值；**不能**直接作为函数实参/`return` 值/三元分支，先赋给变量。
- 字面量元素类型推断：数组/对象字面量的元素可混用数值（如 `[1, 4000000000]` 推断为 `Array<long>`、`[1, 2.5]` 推断为 `Array<double>`）；非数值类型必须严格一致（同质容器）。
- 函数实参**从左到右求值**（codegen 保证副作用顺序）；用户函数实参逐个做类型检查。
- 没有闭包/lambda/用户泛型/接口/元组；函数不是一等值；`??` 未实现（见 §2.4）。
- 整数除零/模零会 panic；运行期整数溢出是二补码 wrap（见 §6.5）。

### 3.6 事件与订阅

```we
on(PingHandler);                 // 推荐：省略 EventType，channel 0
on(PingHandler, 7);              // 推荐 + 指定 channel
once(PingHandler);               // 至多执行一次
off(PingHandler);                // 按 owner 注销

on(PingEvent, PingHandler);      // 显式形式（事件类型必须与 handler 参数匹配）
on(PingEvent, PingHandler, 7);
on(PingEvent, PingHandler, ALL); // 通配所有 channel（仅 on/once/off）

emit(new PingEvent(123) { n: 1 });
emit(ev, 7);                     // 指定 channel
start(ChildController);
stop(ChildController);
```

- **推荐 `on(H)` / `once(H)` / `off(H)`**：从 handler 的 `onEvent(e: T)` 参数自动推断事件类型。
- 显式 `on(Event, H[, channel])`：Event 可以是 handler 参数事件类型本身，**也可以是它的子类**（事件字段展平，handler 只能安全访问基类字段）；反过来（Event 是基类、handler 参数是子类）不允许。
- `emit` 的第一个实参必须是 **event 类型**（`emit(1)` 报 `emit: first argument must be an event`）；channel 不能是 `ALL`。
- channel 是 `long`：0 默认，`>0` 普通，`ALL` 仅用于订阅。
- `emit` 是异步派发；event 的 oid 是调度目标：
  - `new PingEvent(0)`：emit 时用 `IdUtil` 生成新的非 0 oid；
  - `new PingEvent(targetOid)`：直接进入 targetOid 队列，emit 不改写 oid。
- 同一 oid 事件 FIFO 串行，不同 oid 可并行；`once` 在订阅锁内 claim，至多执行一次。
- event 构造后字段冻结：handler 内写 `e.field` 会 panic `write to frozen event`（带 file:line）。

### 3.7 错误模型

- 编译错误：`FILE:LINE:COL: message`。**语句级错误定位到语句起始列；声明级错误（类型名/字段默认值/重复声明等）定位到声明或字段本身**（parser 记录位置；跨文件合并后仍归属到声明所在文件）。
- `wellc check FILE [--json]`：
  - 人类可读模式每行 `FILE:LINE:COL: severity: message`；
  - `--json` 输出单个 JSON 对象 `{"ok":bool,"file":...,"diagnostics":[{file,line,col,endLine,endCol,severity,message,code}]}`；
  - 语义错误**可多条**（按声明/方法收集；同一方法体内仍只报第一条，见 §6.8）；`code` 取值：`semantic` / `parse` / `lex` / `import`（warning） / `internal`（编译器内部异常兜底）。
- 退出码：**0** = 无 error（允许 warning）；**1** = 至少一条 error；**2** = 命令行参数错误/IO 错误（文件不存在或不可读，错误写 stderr，`--json` 时 stdout 为空）。
- handler 内 panic：打印 `well panic: file:line: message`，**只终止当前任务**，调度器继续。
- controller/装配期 panic：未捕获，进程 **exit 70**（`WELL_PANIC_EXIT_CODE`）。
- 没有 try/catch / Result / 异常；可恢复解析用 `Json.tryParse`。

## 4. API 说明

### 4.1 内置函数

| API | 说明 |
| --- | --- |
| `print(...)` | 逐个打印并换行（不自动加空格） |
| `on(H[, channel])` / `on(Event, H[, channel])` | 订阅事件 |

| `emit(event[, channel])` | 异步派发事件 |

### 4.2 Model / Cache / Store

| API | 说明 |
| --- | --- |
| `Model.get(T, oid): T` | Cache 命中返回；未命中从 Store 回源并写 Cache；未命中返回 `null` |
| `Model.peek(T, oid): T` | 只查 Cache，不访问 Store |
| `Model.findByOid(T, oid)` | 兼容别名，语义同 `Model.get` |
| `Model.set(obj)` | 要求 `obj.oid == ctx.oid`；写 Store + Cache（写穿） |
| `Model.remove(T, oid)` | 要求 `oid == ctx.oid`；删 Store + Cache |
| `Cache.get(T, oid): T` | 只查 Cache |
| `Cache.set(obj)` | 只写 Cache（要求 `obj.oid == ctx.oid`） |
| `Cache.remove()` | 删除当前 `ctx.oid` 的全部 Cache 行（所有类型，不动 Store） |

- 全局 Cache 的 key 为 `(type_id, oid)`；默认 Store 是 MemoryStore（进程退出即丢）。
- `Model.get/peek/findByOid`、`Cache.get` 的 oid 实参必须是 `int`/`long`（String 等报错）；`Model.get/peek/findByOid` 额外允许类型名 `Vo`（白名单），`Cache.get` 只接受具体 struct/event。
- Cache 无容量上限/淘汰（由业务自行管理）；TTL 仅保底；oid 完成工作后建议主动 `Cache.remove()`。

### 4.3 Json

| API | 说明 |
| --- | --- |
| `Json.parse(T, text): T` | 按 struct 字段名解析；失败 panic |
| `Json.tryParse(T, text): T` | 失败返回 `null`，不 panic |
| `Json.stringify(v[, indent]): String` | 支持 struct/event/null/标量/顶层 Array/Map/Linked；**顶层容器的元素不能是容器**（嵌套容器通过 struct 字段元数据支持）；indent 0=紧凑、1–8=pretty；非有限 double → null，深度 >64 → null |

- `T` 必须是具体 struct/event 类型；`stringify` 的容器元素类型须是标量或 struct/event；解析失败区分 `parse`（panic，handler 内可隔离）与 `tryParse`（返回 null）。

### 4.4 String / Bytes

```text
String（不可变，字节语义）:
  s[i] / byteAt(i) / charCodeAt(i) / codePointAt(i)
  substring(start, end) / slice(start, end)
  indexOf(sub) / contains(sub) / startsWith(prefix) / endsWith(suffix)
  trim() / toLower() / toUpper() / split(sep) / replace(old, new)
  String.fromByte(b) / String.fromInt(i) / String.fromCodePoint(cp)
  length

Bytes（可变字节缓冲）:
  new Bytes() / length / push(b) / get(i) / set(i, b) / byteAt(i)
  append(other) / appendStr(s) / clear() / toString()
```

- `String` 的 `length`/下标/切片按字节；UTF-8 请用 `codePointAt`/`fromCodePoint`。
- 单次 `a + b` 是 O(n+m)；循环 `s = s + x` 累计 O(n²)，大量拼接用 `Bytes`。

### 4.5 Array / Map / Linked

```text
Array<T>:   push / pop / shift / unshift / get / set / slice / concat / join /
            indexOf / includes / clear / sort / reverse；a[i]、a.length、for (var x of a)
            元素类型：sort 支持 int/long/bool/float/double/String；join 仅 Array<String>
Map<T>:     get / set / has / delete / keys / values / clear；m["k"]、m.size、for (var k in m)
Linked<T>:  pushHead / pushTail / popHead / popTail / head / tail / get / length；for (var x of l)
```

- 越界读返回类型默认值（引用类型返回 `null`）；Array 越界写会扩展。
- 容器写要求 `container.oid == ctx.oid`；插入引用元素要求 `element.oid == container.oid`（String 例外）。
- 不支持 `Map.entries`（需要 tuple/泛型；`m.entries()` 报 `unknown Map method entries`）；用 `keys()` / `values()` / `for (var k in m)`。

```text

    reqId: int/long, method: String, path: String, query: String, body: String
```

- HTTP handler 在 worker 上执行；`Http.respond` 之后不要再次响应。

## 5. 模块说明

### 5.1 语言层：`module` / `import` / 多文件

- `module a.b;` 只是声明，**不参与查找、不构成命名空间**；一个文件只有一条。
- `import` 两种写法：
  - 字符串路径：`import "lib/util.we";`（相对当前文件，`.we` 可省略）；
  - 点路径：`import lib.util;` → 依次尝试 `lib/util.we`、`lib/util/index.we`、同目录 `util.we`。
- 被导入文件的**顶层声明全部合并**进来；可以递归（A import B，B import C → C 的声明也可用）。
- 导入文件里的 `module` 与 `entry` 被忽略；**`entry` 只认根文件**。
- 推荐组织方式（可自由调整）：

  ```text
  src/
    events.we        # event 定义
    handlers.we      # import "events.we"; handler ...
    controllers.we   # import "handlers.we"; controller ...
    main.we          # import 以上 + entry MainController;
  ```

- 循环 import 有去重保护；同一文件只解析/合并一次。
- **声明唯一性**：所有声明共享一个全局命名空间；同一文件或跨文件出现同名声明（任意类别）都是编译错误，错误信息包含首次定义文件（`duplicate declaration 'X' (already defined in ...)`）。
- 无法解析的 import：`check` 输出 `severity=warning, code=import`（退出码仍为 0）；`build` 打印 `wellc: warning: ... unresolved import`，不影响构建。

## 6. 注意说明

### 6.1 oid 所有权与写检查

- 每个 struct/event/容器对象都有 `oid`（`long`），表示数据所有者；`new T()` 的 `oid = ctx.oid`。
- 写规则：
  - 字段写：`target.oid == ctx.oid`；
  - 引用字段/容器元素写：`value.oid == target.oid`（String 例外，null 允许）；
  - 容器写：`container.oid == ctx.oid`；
  - Model/Cache 写：对象/oid 必须等于 `ctx.oid`。
- 违规会 panic（`well oid violation`）；不要跨 oid 引用业务对象。
- event 构造字段豁免 oid 检查（可以携带异 oid 的只读引用），构造后冻结。

### 6.2 event 的 oid 与 static

- `new PingEvent(0)`：oid=0，**emit 时**才由 `IdUtil` 分配新的非 0 oid；
- `new PingEvent(targetOid)`：直接使用 targetOid，emit 不改写；
- 因此 oid=0 的 event 不要放进 static/装配期数据（最终 oid 到 emit 才确定）；
- static 不能持有 event 类型（直接/容器/struct 间接都不行）。

### 6.3 static / 装配期

- 启动顺序：运行时 init → 类型注册 → static owner oid 设置（当前 0）→ static init → 模块 init → controller run → 事件循环；
- 事件循环开始时 static 冻结：启动期可写，运行期只读；
- static 数据永不参与 TTL 回收，退出时统一释放；
- 运行期可变状态请用 Model/oid。

### 6.4 RC / TTL / 内存

- 引用计数（原子 RC）：`new` 为 1；变量/字段/Model 持有 +1，释放 -1；
- handler 帧日志统一释放临时引用；handler/event 执行期间对目标 oid 做 pin（`exec_ref`），不会被 TTL 回收；
- TTL 默认 60s（`WELL_MODEL_TTL_MS`，0 关闭）：oid 空闲 + `exec_ref==0` + 调度器空闲时整组回收；
- 主动释放：oid 完成工作后调用 `Cache.remove()`（只删 Cache 行，Store 不变）；TTL 只是最后保底；
- 允许成环，环最终由 TTL 兜底回收；
- Cache 无容量上限/淘汰（**业务自行管理**）。

### 6.5 整数 / 除零 / 溢出

- 整数 `/`、`%` 除零 → panic（带 `file:line`）；字面量常量除零/常量溢出 → 编译错误；
- 运行期 `+ - *` 溢出按**二补码 wrap**：gcc/clang 构建始终追加 `-fwrapv`，TCC 的代码生成本身即 wrap；
- 编译期字面量常量算术溢出仍是编译错误；业务需要范围保证时请显式检查（语言不提供 checked 模式）。

### 6.6 String / 容器

- `String` 不可变、按字节；`length`/下标/切片单位是字节；
- 循环拼接用 `Bytes`，不要用 `s = s + x` 累积大字符串；
- 容器字面量不能直接当函数实参/普通 struct 字段初始化值，先赋给变量；
- 越界读返回默认值；不要依赖越界写行为。

### 6.7 未实现/不要使用

- `??` 空值合并：**语法保留但未实现**（checker 明确报错）——用 `x == null ? y : x`。
- 可空类型 `T?`：语法可解析，但 checker **不检查**（等同 `T`），没有 null 收窄；不要依赖。
- 无异常/try-catch/Result；无用户泛型/接口/元组/闭包/lambda；无 `defer`/字符串插值；无 async/await/协程。
- 无 `Map.entries`、无 `char/short`、无独立的 `float`（float 与 double 同为 C double）。
- `->` 保留给 lambda/管道（未实现，写出即编译错误）；
- `controller`/`handler` 不支持 `extends`（语法已移除，写了编译错误）；struct/event 只支持字段展平、无多态。
- 容器字面量不能直接作实参/`return` 值；没有类型转换/cast 语法（窄化直接报错）。
- 无持久化后端（仅 MemoryStore）/无热更新/无模块卸载；`invoke` 已从语言删除（D-21）。

### 6.8 已知边界 / 坑（当前实现）

1. **entry 在根文件**：导入文件中的 `entry` 被忽略；根文件无 entry 时 `check` 通过、`build` 也能生成 exe，但运行时报 `no entry controller` 退出 1。
2. **编码**：`.we` 源码按 UTF-8 读取，**允许带 BOM**（lexer 会跳过 U+FEFF）；换行 LF/CRLF 均可。
3. **诊断精度**：语义错误定位到语句起始列（表达式内部不精确到 token）；声明级错误定位到 decl/字段；`check --json` 可报多条，但**同一方法体内仍只报第一条**（FE-P2-18 残留），`build` 也只输出第一条 message（顺序=检查顺序）。
4. **IO 错误退出码**：文件不存在/不可读时 `check` 退出码为 **2**（stderr 输出错误；`--json` 时 stdout 为空），与约定一致。
5. **三元 `?:`**：条件必须为 bool/int/long；两分支必须同型、或均为数值（按 widening 合并）、或一方为 `null` 且另一方为引用类型；不兼容报 `ternary branches have incompatible types`。
6. **handler 事件方法唯一性**：`onEvent`/`handle`/`on`/`handler` 同时定义多个会报编译错误（不再静默忽略）。
7. **Blocking I/O**：`File.*`/`Mysql.*` 同步调用会占住 worker；handler 是 run-to-completion，没有让渡/超时。
8. **日志/输出**：`print` 串行化输出；`Host.log` 写 stderr。
9. **环境变量**：`WELL_WORKERS`（worker 数，默认 `max(1, cores*3/4)`）、`WELL_CC`、`WELL_CFLAGS`、`WELL_SERVER_ID`、`WELL_MODEL_TTL_MS`、`WELL_POOL_*`、`WELL_RC_DEBUG=1`（退出时打印 live objects，正常为 0）。
10. **C 名称修饰**：Well 名与 C 名不再冲突（自动加前缀）；但 C 需要合法标识符，非 ASCII 标识符虽可编译（TinyCC 实测可用），跨编译器建议用 ASCII。

---

## 7. 命名规范（推荐，非强制）

| 声明 | 规则 | 示例 |
| --- | --- | --- |
| `struct` | PascalCase + `Vo` 结尾 | `UserVo`、`OrderItemVo` |
| `event` | PascalCase + `Event` 结尾 | `UserEvent`、`PingEvent` |
| `controller` | PascalCase + `Controller` 结尾 | `UserController` |
| `handler` | PascalCase + `Handler` 结尾 | `UserHandler` |
| `enum` / `namespace` / `static` | PascalCase | `OrderStatus`、`StringUtil`、`AppConfig` |
| 字段/方法/变量 | lowerCamelCase | `userId`、`onEvent`、`itemCount` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRY` |

内置 API、HTTP/WS 事件字段名（`reqId`、`clientId`、`method`、`path`、`query`、`body`、`text`、`code`、`reason`）是与运行时/协议约定的字段，**不能改名**。

## 8. 最小示例

```we
module demo.hello;

struct HelloVo {
    id: long;
    name: String;
}

event HelloEvent {
    userId: long;
}

handler HelloHandler {
    onEvent(e: HelloEvent) {
        var vo: HelloVo = Model.get(HelloVo, e.userId);
        if (vo == null) {
            vo = new HelloVo();
            vo.id = e.userId;
            vo.name = "well";
            Model.set(vo);
        }
        print("hello ", vo.name);
    }
}

controller MainController {
    run() {
        on(HelloHandler);
        emit(new HelloEvent(0) { userId: 7 });
    }
}

entry MainController;
```
