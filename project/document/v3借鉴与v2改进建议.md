# v3 借鉴与 v2 改进建议

日期：2026-10-24  
范围：WellLangV3 源码/实验记录对 WellLangV2 的可借鉴项。  
结论：**v3 的受限 region、绑定槽位 journal、源码 TLS、MySQL 读缓冲和实验方法值得学习；v3 的普通 RC/数组实现不应照搬。v2 应先补 journal 正确性，再做低风险性能项，最后才考虑 region。**

## 1. v3 值得学习的内容

### 1.1 调用内回收区（region）

源码：`E:\Work\WellLangV3\project\compiler\runtime\core\well_region.c`

设计要点：

- 16 KiB chunk，按 16 B size class 分配；
- 已死 slot 在调用内立即复用，不是函数返回才回收的 bump arena；
- 每个 region 有私有 RC，对象带 `WELL_FLAG_LOCAL`；
- region 挂在父 ctx 上，可沿调用链清理；
- panic 时通过父链回收未 journal 的对象；
- 离开函数时 sweep 全部 slot，并精确释放外部数组 backing buffer；
- 只对编译器证明**不会逃逸**的函数启用。

v3 自己的实验数据：

- 持续分配：141 → 72 ms；
- LTO 后：70 → 28 ms；
- 第一版“所有 confined 函数都开 region”导致短调用回归 **>3×**，被回滚；
- 最终激活条件：固定次数循环、至少 256 次分配、无 break/return/计数器改写。

**值得学的是设计 + 成本模型，不是无条件开启。**

### 1.2 绑定槽位 journal

v3 文档：`project/tool_ai/JOURNAL_SLOTS_NEXT.md`  
v3 实现：`well_ctx_replace_at`、按绑定索引的 journal。

v3 用毒化测试证明了三类继承自 v1 的问题：

1. callee 重新赋值 borrowed reference 参数；
2. 嵌套别名指向同一对象；
3. 外层 null 变量在循环内赋值。

v2 当前仍是“按旧指针地址扫描”：

`E:\Work\WellLangV2\project\compiler\runtime\core\wellrt.c:864`

```c
for (i = 0; i < ctx->n; i++) {
    if (ctx->refs[i] == old) { found = i; break; }
}
```

v3 的结论是：**地址相等不等于绑定身份**。v2 的 189 个测试通过，但未覆盖这些别名场景。

建议：先移植 v3 的毒化测试到 v2；若复现，改为绑定槽位。

### 1.3 源码位置原生 TLS

v3 在 Clang/GCC 下：

```c
static __thread const char *g_src_file;
static __thread int g_src_line;
```

TCC 保留 OS TLS-key fallback。

v2 当前：

`E:\Work\WellLangV2\project\compiler\runtime\core\wellrt.c:473`

```c
well_tls_set(g_src_file_key, (void *)file);
well_tls_set(g_src_line_key, (void *)(intptr_t)line);
```

每个 source-position 更新两次 OS TLS 调用。v3 的 v1 基线实验显示 93 → 53 ms；v2 已有 lazy ctx marks，收益会小一些，但这是低风险项。

### 1.4 LTO 作为显式配置

v3 推荐：

```text
-O2 -fwrapv -flto
```

v3 实验：分配 70 → 28 ms（约 -60%）。  
v3 同时明确：**LTO 保持显式，不默认开启**。

v2 `--release` 当前是：

```text
-O2 -fwrapv -DWELL_NO_OID_CHECK=1
```

没有 `-flto`。

### 1.5 MySQL 小包读缓冲

v3 的 `WellMysqlConn` 有 8 KiB `read_buf`：

- 小包从缓冲拷贝；
- 大包/大结果直接读到目标 buffer，避免二次拷贝；
- 单连接标量查询：127.7 → 113.1 ms（-11.5%）。

v2 当前 `my_read_all` 是按请求长度逐次 `recv`，没有预读：

`E:\Work\WellLangV2\project\compiler\runtime\modules\mysql\well_mysql.c:230`

```c
int k = my_recv(c->fd, b, (int)n);
```

### 1.6 实验方法

v3 的做法值得直接借鉴：

- 每场景 5 个独立进程 × 7 轮，前 2 轮预热；
- 轮换语言/配置顺序；
- 保留旧二进制，交替 A/B；
- 报告 min–max、中位数、原始 JSON/日志、固定提交；
- C 测试强制 `-UNDEBUG`，避免 `-O2` 下 `assert` 被编译掉。

v2 现有结果很多是 2–3 次快速运行，不足以判断 3–5% 的差异。

## 2. v2 现状与差距

| 方向 | v2 现状 | v3 做法 | 优先级 |
|---|---|---|---|
| 生命周期 journal | 按旧指针地址扫描 | 绑定槽位 | **P0** |
| 源码位置 | 两次 OS TLS 写 | Clang/GCC 原生 TLS | P1 |
| LTO | `--release` 无 LTO | 显式 LTO | P1 |
| MySQL 读 | 精确 recv | 8 KiB 缓冲 + 大包直读 | P1 |
| 调用内分配 | 栈/区域仅限小的非逃逸对象 | 受限 region + 私有 RC | P2 |
| 短调用成本 | 已有栈路径 | region 有成本门槛 | P2 |
| 测试方法 | 189 用例为主 | 5×7 + 专项契约 | P1/P3 |

## 3. 建议修改内容

### P0：绑定槽位 journal（正确性）

目标：修复别名/参数/null/foreach 生命周期问题，不改变语法和自动回收。

建议改动：

1. `WellCtx` 增加稳定的绑定槽位表；codegen 为每个引用绑定分配 slot index；
2. 新增 `well_ctx_replace_at(ctx, index, new_value, owned)`；
3. codegen 在以下位置使用 slot：
   - 引用参数入口；
   - `var` 引用声明；
   - null 引用声明（必须预留空 slot）；
   - for/foreach 初始化；
   - 嵌套 block 的 shadowing；
   - break/continue/return 的恢复路径。
4. 保留现有 `well_ctx_replace` 作为兼容入口，内部按 slot 处理，避免一次性改所有调用点。

验收：

- 移植 v3 的 `check_journal_aliases` 等价测试；
- callee 改参数、嵌套别名、外层 null 循环赋值都返回正确值；
- 毒化对象在仍被引用时不得被销毁；
- 正常 return / early return / panic / OOM 下 live object 和 temp journal 归零；
- 现有 189 用例 + C 测试通过。

### P1：源码位置 TLS

目标：减少每次 `well_source_set` 的两次 OS TLS 调用。

建议改动：

```c
#if defined(__GNUC__) || defined(__clang__)
static __thread const char *g_src_file;
static __thread int g_src_line;
void well_source_set(const char *file, int line) {
    g_src_file = file;
    g_src_line = line;
}
/* src_file_get/src_line_get 直接读 */
#else
/* 现有 WellTlsKey 路径，供 TCC 使用 */
#endif
```

验收：

- 20 对线程的 source-position 隔离测试；
- panic 位置仍准确；
- Clang/TCC 两条路径都通过；
- 基准：CPU 循环、HTTP/WS 请求路径，确认无回归。

### P1：LTO opt-in

目标：让 v2 也能使用 LTO，但不改变默认构建。

建议改动：

- `wellc build` / `run` 增加 `--release-lto`，或环境 `WELL_RELEASE_LTO=1`；
- flags：`-O2 -fwrapv -flto -DWELL_NO_OID_CHECK=1`；
- 保持现有 `--release` 不变，便于 A/B；
- C 测试 runner 加 `-UNDEBUG`。

验收：

- CPU、容器、HTTP、WS、JSON 各 3–5 轮；
- 与 `--release` 非 LTO 对比，报告 min/median/max；
- 短调用、panic 路径、C 测试全部通过；
- 若无稳定收益，保持 opt-in，不默认开启。

### P1：MySQL 小包读缓冲

目标：减少 syscall/拷贝，改善单连接和小结果查询。

建议改动：

1. `WellMysqlConn` 增加：

```c
char read_buf[8192];
size_t read_pos, read_end;
```

2. `my_read_all`：
   - 小请求从 `read_buf` 拷贝；
   - 大请求（`n >= sizeof(read_buf)`）直接 `recv` 到目标 buffer；
   - 保持 EOF/timeout 语义；
3. 连接池销毁时无需额外释放（buffer 内嵌）。

验收：

- 单连接 5,000 次标量查询；
- 大结果集/大 body 不额外放大内存；
- 连接池、断线、超时测试；
- 与 C/C++/Java/Go/Erlang 同 SQL/同实例基准。

### P2：窄范围 region

目标：覆盖“长循环、大量局部对象”的分配，不破坏短调用。

**不要第一版就全量启用。**

建议范围：

- plain scalar struct；
- 一层标量数组；
- 参数/返回值为标量；
- 对象不能逃逸调用，不能进入 Model/event/static/容器返回值；
- 固定次数循环、至少 256 次分配、无 break/return/计数器改写。

实现建议：

- 新增 `well_region.c/h`，参考 v3：
  - 16 KiB chunk；
  - size-class free list；
  - 私有 RC；
  - `WELL_FLAG_LOCAL`；
  - parent/panic 链；
  - leave sweep；
- codegen 加 `local_effects` 风格的 fail-closed 证明；
- 保留 v2 现有内联 4 元素数组/Map，不要换成 v3 的 `items=NULL` 实现；
- 增加 `WELL_LOCAL_ALLOC=0` 开关做 A/B。

验收：

- 短调用回归不超过 3%；
- 持续分配提升；
- 逃逸负例全部走普通路径；
- panic/OOM/多 worker/外部 buffer 精确释放；
- 高水位内存有界；
- 保留旧二进制做交替 A/B。

### P3：测试与基准

建议新增：

- retained-ring 分配（保留 1,024 个对象并替换）——这是 v3 的强项场景，v2 现有“每次 new/release”测不出来；
- journal alias 毒化测试；
- region/panic/OOM 契约；
- atomic memory 1/2/4/12 线程契约；
- HTTP/WS 5×7 轮换；
- C 测试 `-UNDEBUG`；
- 原始 JSON、日志、固定提交、旧二进制保留。

## 4. 不建议照搬

1. **不要照搬 v3 普通 retain/release**：v3 是 `atomic_load + atomic_inc/dec`，v2 是单次 RMW；v2 这条更省。
2. **不要照搬 v3 数组实现**：v3 数组没有内联 4 元素；v2 的内联数组在小容器上更快。
3. **不要默认开 LTO/region**：v3 自己保持 LTO 显式、region 需成本证明。
4. **不要把 v3 的 27 ms 分配和 v2 的 39 ns/60 ns 直接比较**：workload 不同（替换并保留 1024 对象 vs new/release + 逃逸）。
5. **不要用 v3 局部场景推断整体语言排名**：v3 最新报告也已承认 v2 在数组、逃逸分配、小容器上的优势。

## 5. 建议实施顺序

1. **P0 journal 绑定槽位**（正确性，先做）
2. **P1 源码 TLS**
3. **P1 MySQL 读缓冲**
4. **P1 LTO opt-in**
5. **P2 窄范围 region**
6. **P3 测试/基准方法**

每一步都：

- 先保留旧二进制；
- 同机交替 A/B；
- 跑 189 用例 + C 测试；
- 提交可回滚 commit；
- 无稳定收益则 revert，不保留“看起来更优”的改动。
