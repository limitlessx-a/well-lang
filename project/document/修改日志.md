# WellLang 修改日志

> 约定：每次修改（功能、修复、优化）完成后，在本文件顶部追加一条记录，并随该次修改一起 git 提交。
> 记录格式：日期 + 类型 + 摘要 + 涉及模块/文件 + 验证结果（commit 可在 git log 中查，历史条目保留 hash 供参考）。

## 2026-10-22

### [功能] 核心定时器 Timer.once / Timer.loop / Timer.cancel
- 新增 `runtime/core/well_timer.c`：timer 线程（懒启动、约 5ms 轮询、`well_shutdown` 时 join）、timer 链表、到期以 timer id 为 oid 投递 task
- 编译器新增内建 `Timer.once(ms,H): long`、`Timer.loop(ms,H): long`、`Timer.cancel(id)`；每个调用点生成 `timer_fire_N` wrapper，按事件字段名回填 `id/interval/fires`
- 生命周期：有 timer 注册时 timer 线程持有 service 计数，全部结束/取消后释放；到期时**先投递 task 再释放 service**，避免 run loop 在 task 入队前提前退出（压测中修复的一处竞态）
- 新增测试 `68_timer_once`（once + 取消一个未到期 timer）、`69_timer_loop`（loop 触发 3 次后自行 cancel），均带 rc_debug=0
- 文档：IMPLEMENTATION§2.5/§3.17、README、线程模型文档、路线图
- 验证：69/69 用例 + C 测试

### [优化] HTTP 每连接复用缓冲区 + reqId 哈希
- 连接 reader 线程复用一个 64KB 缓冲区（原为每请求 malloc）；request line/target/query 原地切分，不再 strdup；body 仍复制
- 请求 id 改为开放寻址哈希（Knuth 后移删除），`Http.respond` 从 O(n) 扫描变 O(1)
- 验证：67/67 用例 + C 测试；keep-alive 吞吐 ~14.5k req/s（基本不变，本次主要为扩展性）
- commit `098e01f`

### [功能] HTTP keep-alive + 每连接 reader 线程
- listener 只做 accept，每连接一个 reader 线程；HTTP/1.1 默认 keep-alive、15s 空闲超时、`Connection: close` 关闭
- 响应按请求输出 `Connection` 头；reader 等响应写出（`written`）后再读下一请求，响应不交错
- 请求/连接引用计数 + 每连接 service 计数；`Http.stop` 用 `shutdown()` 让 reader 自己关 socket
- 新增测试 `67_http_keepalive`；测试客户端改为按 Content-Length 读单个响应
- 验证：67/67；keep-alive 吞吐 175 → ~15000 req/s
- commit `280ff8c`

### [优化] String 字节长度缓存 + HTTP 解析器性能基线
- `WellString.len` 缓存字节长度，`s.length`/`s[i]`/`trim`/`startsWith`/`endsWith`/`split` O(1)，避免解析循环 O(n²)
- 新增 `String.fromInt(n)`
- Well HTTP 解析器移入 `examples/lib/http_parser.we`，新增 `examples/http_parser_bench`
- 基线：C 0.75µs/次 vs Well 13.3µs/次（≈18×，瓶颈是每字段分配）；文档 `document/HTTP-解析器性能基线.md`
- 验证：67/67（含 rc_debug=0）
- commit `6879f41`
