### [修复] P0 编译器正确性检查（审计 A1–A6）
- **A1 返回类型检查**：`return` 的值必须可赋给声明的返回类型（`func f(): int { return "abc"; }` 现在编译错误 `cannot assign String to int`，此前会静默输出指针值）
- **A2 全路径 return**：非 void 函数要求所有路径都返回值（`if` 需有 `else` 且两分支 return），否则 `not all paths return a value`
- **A3 类型名统一校验**：struct/event 字段、func/handler/controller/namespace/static 的参数与返回类型、const 类型全部走 `check_type_name`；未知名报 `unknown type`（此前泄漏成 C 编译错误）
- **A4 重复声明检测**：同一 `.we` 文件内重复声明（类型/func/controller/handler/namespace/static/enum/const）报 `duplicate declaration`（此前 driver 合并时静默保留第一个）
- **A5 break/continue 位置**：循环外使用报 `break/continue outside of a loop`（此前泄漏成 C 错误）
- **A6 容器字面量作实参**：改为明确 checker 错误（提示先赋给变量），不再抛 Python traceback
- 新增编译错误测试 `79–84`；全量 **84/84** + C 测试通过
- 审计文档 `document/核心代码审计.md` 标记 A1–A6 已修复

### [功能] `static` 静态类：可写字段 + 函数（config / 工具类）

### [功能] 静态函数集合 `namespace`
- 新关键词 **`namespace`**（讨论后选定；备选 `funcs`，切换只需改 lexer 关键词表 + parser 分支两处）
- 语法：`namespace N { f(a:int):int { ... } }`，调用 `N.f(...)`；namespace 内可按名字直接调用同 namespace 的其他函数；成员暂只允许函数（不放 const/enum/struct），不支持嵌套/别名/重载

- 测试：`71_namespace`（加减、同 namespace 互调、String 返回；rc_debug=0）、`72_namespace_error`（实参个数编译错误）
- 文档：IMPLEMENTATION §2.1、README、路线图；验证：72/72 + C 测试

### [优化] HTTP 同步响应快速路径（TLS 当前请求 + 引用统一释放）
- `well_http.c`：http task 进入 handler 前把当前请求写入线程局部 `g_current_req`；`Http.respond` 命中同 reqId 时跳过全局请求哈希锁，直接写响应（异步业务 oid 响应仍走哈希）
- 引用所有权调整：响应者不再释放请求引用，统一由连接线程在 `written` 后释放（thread + list 两个引用），减少每请求 1–2 次全局锁
- 并发压测（C 客户端，N 进程单连接）：workers=1 时 4 客户端聚合 37k → **42–58k req/s**；raw C 基线 86.6k
- 结论：短 handler 下默认 workers=1 最优；多 worker 因线程超订 + 调度器单锁，在小负载下反而更慢（per-worker 锁属待确认的结构优化）
- 文档：性能基线 §4.4；验证：69/69 + HTTP 压测 3 轮
