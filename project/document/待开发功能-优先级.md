## 1. 当前状态

### 编译器

```text
.we -> C99 -> TinyCC / gcc
lexer / parser / checker / codegen / driver
```

已支持：

- struct / event / enum / controller / handler / func / **namespace** / **static** / import；`switch/case`（无 fallthrough、int/long/String、case 常量与重复检查）；
- if / while / for / of / in / break / continue / return；`for (var x of a)` / `for (var k in m)`；
- String、Bytes、Array、Map、Linked；`Json.parse/tryParse/stringify`；enum `fromInt/toString`（含显式 `enum E: int|long|String` 与 String 枚举成员作值/case）；
- 事件订阅：推荐 `on(H[, C])` / `once` / `off`（从 `onEvent(e: T)` 推断事件类型）；也支持 `on(EventType, H[, C])`，EventType 可为 handler 参数事件类型本身或其子类；
- **类型系统（2026-10-23 审计修复）**：带注解 `var` 必须与初始值兼容；用户函数实参/返回值/字段默认值/容器元素逐项校验；数值只允许 widening（bool→int→long→double），窄化报错；`null` 只能赋给引用类型；`void` 只能作返回类型；`if/while/for` 条件必须 bool/int/long；比较/逻辑/算术/`%` 有明确操作数规则；`T?` 仅语法保留（checker 忽略）；
- **声明/作用域**：同文件与跨文件同名声明（任意类别）都是编译错误；参数重名/同作用域 var 重名报错；内层遮蔽允许；controller 只能 `run()`，handler 只有一个事件方法且参数必须是具体 event 类型；`const` 必须是编译期常量；struct/static 字段默认值只允许字面量/const/容器字面量/`new Bytes|Array|Map`；
- **诊断**：语义错误带 `FILE:LINE:COL`（语句级/声明级）；`check --json` 可多条诊断；退出码 0/1/2；内部异常兜底为 `internal` 诊断；
- static 完整语义：装配期（启动 ctx oid，当前 0）可写、运行期冻结只读；值 oid 必须等于装配期 oid（String 例外）；引用字段禁止 event（直接/容器/struct 间接）；默认值支持字面量/const/容器字面量/new Bytes/Array/Map；装配期 oid 不参与 TTL 清理；
- **codegen 命名/求值**：C 符号加类别前缀（`wt_/wf_/hd_/ctl_/E_/C_/wst_/v_/f_`），Well 原名保留在元数据/JSON 中；实参从左到右求值；复合赋值目标只求值一次；for-of/for-in 迭代源只求值一次；产物名 `<stem>_<hash8>` 避免不同目录同名覆盖；
- oid 写入检查、Struct 元数据、行级序列化、JSON 解析、File/Host、HTTP/WS/MySQL 基础 API；
- 局部作用域释放、覆盖赋值释放、临时值所有权（take + 每帧临时栈）。

### 运行时

```text
RC（原子引用计数）
+ oid exec_ref（执行引用租约）
+ oid registry（按 oid 枚举对象）
+ 过期数据回收（TTL 保底，默认 60s；oid 空闲且 exec_ref == 0 时整组回收）+ 语言层 `Cache.remove()` 手动释放
+ 固定大小对象池（env 缓存 + 1s 节流 sweep）
+ 帧日志（WellCtx 内联 16 ref + 4 pin，溢出才堆分配）
+ 调度器（每 oid FIFO、per-worker deque、work stealing、单调度锁）
+ 原生条件变量（Windows CONDITION_VARIABLE 动态加载 / POSIX pthread_cond）
+ Timer（once/loop/cancel，独立 timer 线程）
```

内存关系：

```text
全局 Cache: (type_id, oid) -> 对象      （无容量上限/淘汰：用户自行管理，见 §4）
MemoryStore: (type_id, oid) -> 编码字节 （纯后端）
Model: Cache / Store 组合转发（当前仍是全局单 Model）
```

## 5. 后续候选（按 §0.2 顺序讨论）

### 5.1 语言/语法

- ✅ `switch/case`（无 fallthrough、int/long/String，case 值常量检查与重复检查；String 枚举成员可作 case）；
- ✅ enum `fromInt/toString`（int 枚举 fromInt/toString；String 枚举 toString；显式 `enum E: int|long|String` 校验）；

## 6. 关键约定（当前运行时）

### 6.1 oid / IdUtil

- oid 固定 `long`，由 `IdUtil.getId()` 生成（serverId + timestamp + sequence）；
- `WELL_SERVER_ID` 0..1023；同 oid FIFO、单 runner，异 oid 并行；
- 装配期 oid = 启动 ctx.oid（当前 0，未来可变），装配期数据永不参与 TTL 清理；
- oid 不是 MySQL 主键；业务键才是 DB 主键。

### 6.2 Cache / Model / Store

- Cache 全局共享，key `(type_id, oid)`，不记录来源；
- 当前运行时仍是**单全局 Model + 单 Store**；
- `Model.get` 先查 Cache，miss 时 Store.select → Cache.set；`Model.peek` 只查 Cache；
- `Model.set` 先 Store.upsert 再 Cache.set；`Model.remove` 先 Store.delete 再 Cache.remove；
- MemoryStore 纯后端，不查 Cache；Cache 无容量上限/淘汰（用户自行管理，见 §4）。

### 6.3 GC / TTL / 内存

- RC 保留；对象 rc0 后进入固定大小对象池（env 缓存、1s 节流 sweep）；
- oid 维护 `exec_ref`（handler/event 持有 +1、释放 -1）与 `last_active`（只由 Cache.get/set 更新）；
- TTL 默认 60s（`WELL_MODEL_TTL_MS`，0 关闭）；过期条件：TTL 到期 + exec_ref==0 + 调度器空闲；
- 满足后 registry 中该 oid 全部对象回收，Cache 行 discard，Store 字节保留；
- 语言层手动释放：oid 完成工作后调用 `Cache.remove()`（只删 Cache 行，Store 不变）；TTL 仅最后保底；
- 清理：单飞 + 分批（`WELL_MODEL_TTL_BATCH` 默认 64）；每个 oid 隔离后短锁摘除元数据，**锁外释放对象**，不阻塞其他 oid；
- 装配期 oid 数据永不回收；环由 TTL 兜底（默认开启）；
- 帧日志：`WellCtx` 内联 16 ref + 4 pin；
- 池：`WELL_POOL_TTL_MS` 到期真正 free；`WELL_POOL_MAX_MB` 上限。

### 6.4 事件 oid / 订阅

- event `oid` 必须非 0；`new Event(0)` / emit 前 oid=0 时用 `IdUtil` 自动生成；
- 所有 event 统一进入 oid 队列调度；
- 订阅支持 `on/once/off(Handler[, channel])` 与显式 `(EventType, Handler[, channel])`；二参时首参是 handler 名按 `(Handler, channel)` 解释；
- `emit` 异步派发；在 run loop 之前 `off` 会取消尚未派发事件的投递。

### 6.5 元数据 / 序列化 / JSON

- 每个 struct/event 生成 `WellTypeDesc`/`WellFieldDesc`；行级二进制格式 `WLS1`；C 字段名 `f_` 修饰、Well 原名保留在元数据；
- JSON：`Json.parse`（失败 panic）、`Json.tryParse`（失败返回 null）、`Json.stringify`（struct/event/null/标量/顶层 Array/Map/Linked；嵌套容器经字段元数据；非有限 double→null、深度>64→null）；ref 编码为 `type_id + oid`，解码用 resolver；未知字段跳过有深度限制；
- namespace/static 编译期解析：`N.f(...)` → `static wf_N__f`，`S.f`/`S.m()` → C 全局变量/静态函数；零运行时开销。

### 6.6 网络 / MySQL / 平台限制

- HTTP：多连接 + keep-alive（15s 空闲）、连接上限 1024、16KB 请求头上限、头部/发送/响应超时、首响应 + 5s 504；**无 TLS/chunked/pipelining 并发**；
- WS：每连接 reader 线程、text frame、独立端口；握手 10s/空闲 60s/发送 15s 超时、连接上限 4096；分片/二进制帧以 1003 关闭；无 TLS/背压/同端口 Upgrade；关闭路径堆损坏已修复（B16/对象池 size class）；
- MySQL：native auth、COM_QUERY、连接池（健康检查）；连接 5s/IO 15s 超时；无 TLS/prepared/事务 API；
- 最终部署目标 Linux；Windows 本机用 TCC/gcc 验证，POSIX 由 Linux CI（gcc -O2，完整回归：188 `.we` + 18 C 测试 + check-cli）验证；POSIX 分支另用 NDK clang 交叉做语法检查；
- Windows 条件变量为原生 `CONDITION_VARIABLE`（动态加载，Vista+）。

### 6.7 语言检查边界（当前）

- **类型系统**：注解 var 初始化、用户函数实参、返回值、const 初始化、struct/static 字段默认值逐项校验；数值只允许 widening，窄化报错；`null` 只能赋给引用类型；`void` 只能作返回类型；`if/while/for` 条件必须 bool/int/long；比较/逻辑/算术/`%` 有操作数规则；根类型不能作值类型；Cache/Model oid 必须 int/long；
- **声明/作用域**：全局单命名空间（同文件/跨文件同名任意类别报错）；参数重名、同作用域 var 重名报错；内层遮蔽允许；controller 只允许 `run()`；handler 单一事件方法且参数须具体 event；`const` 必须是编译期常量；struct/static 默认值受限；容器字面量仅 var/赋值/默认值上下文；
- **诊断**：语句级/声明级 `FILE:LINE:COL`；`check --json` 可多条；退出码 0/1/2（IO 错误码有已知偏差）；同方法体内仍首错即停；
- 整数除零已检查（panic + 位置）；编译期常量溢出报错；运行期溢出为二补码 wrap（gcc/clang `-fwrapv`，TCC 同）；
- switch/case（无 fallthrough）、enum fromInt/toString、String 枚举成员作值/case 已支持；剩余：异常/Result、泛型、接口、显式 cast、defer、字符串插值、可空类型 `T?`、`??`（暂不实现）。
