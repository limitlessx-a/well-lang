## 0. 当前状态

### 编译器

```text
.we -> C99 -> TinyCC / gcc
lexer / parser / checker / codegen / driver
```

已支持：

- struct / event / enum / controller / handler / func / **namespace** / **static** / import；
- if / while / for / of / in / break / continue / return；
- String、Bytes、Array、Map、Linked；
- 事件订阅：`on(EventType, H[, C])` 与 **`on(H[, C])` / `once` / `off`**（从 `onEvent(e: T)` 推断事件类型）；
- 编译期类型/语义校验（P0 批次）：
  - return 值类型与声明返回类型一致；
  - 非 void 函数所有路径必须 return；
  - struct/event 字段、func/handler/controller/namespace/static 参数与返回、const 类型名校验；
  - 同一文件重复声明报错；
  - break/continue 必须在循环内；
  - 容器字面量作实参给出明确错误（暂不支持，提示先赋变量）；
- oid 写入检查、Struct 元数据、行级序列化、JSON 解析、File/Host、HTTP/WS/MySQL 基础 API；
- 局部作用域释放、覆盖赋值释放、临时值所有权（take + 每帧临时栈）。

### 运行时

```text
RC（原子引用计数）
+ oid exec_ref（执行引用租约）
+ oid registry（按 oid 枚举对象）
+ 强制清理（oid 过期且 exec_ref == 0）
+ 固定大小对象池（env 缓存 + 1s 节流 sweep）
+ 帧日志（WellCtx 内联 16 ref + 4 pin，溢出才堆分配）
+ 调度器（每 oid FIFO、per-worker deque、work stealing、单调度锁）
+ 原生条件变量（Windows CONDITION_VARIABLE 动态加载 / POSIX pthread_cond）
+ Timer（once/loop/cancel，独立 timer 线程）
```

内存关系：

```text
全局 Cache: (type_id, oid) -> 对象      （无容量上限/淘汰，见 §2.6）
MemoryStore: (type_id, oid) -> 编码字节 （纯后端）
Model: Cache / Store 组合转发（当前仍是全局单 Model）
```

## 2. 接下来：正确性与语言核心优先

> 依据 [核心代码审计.md](document/核心代码审计.md) 的 P0–P3 顺序；HTTP/WS/MySQL 测试按用户要求暂缓。

### 2.1 P0 错误处理基础

- `Json.parse` 增加可失败版本（`Json.tryParse`/`null` 返回）或错误码，避免只能 panic；
- panic 信息带源码位置/类型（checker/runtime 编译期记录）；
- controller `run`/装配期 panic：记录错误、明确退出码、可选继续启动其他 controller；
- 后续再考虑 try/catch/Result 语法；
- 验收：坏 JSON 不杀进程；panic 信息可定位；controller panic 退出码明确。

### 2.2 P0 继承体系

**controller / handler 方法继承**

- `extends` 当前只被语法接受，没有方法继承；
- 子 controller/handler 应继承父类方法，可覆盖，多级继承，缺失方法报错；
- 验收：父类 `run/onEvent` 可继承、子类可覆盖，现有用例不回归。

**event 继承与子类派发**

- event 继承关系；订阅父 event 是否接收子 event；
- 精确 type_id 派发 vs 层级派发策略；
- 验收：父/子 event 订阅语义明确。

### 2.3 P1 语法完整性

- `switch/case`；
- enum `fromInt/toString`；
- null 收窄（`T?` 当前仅标注）；
- 容器字面量实参（当前明确报错，后续支持：`f([1,2,3])`）；
- 数值类型补齐：char/short/float；
- 验收：每个语法点有 .we 用例；不破坏 oid/所有权规则。

### 2.4 ~~P1 invoke~~（不做）

- 决定：**不实现同 oid 同步调用**；`invoke` 已从语言中删除（D-21），不再作为待开发项；
- 计算用 `func`，跨 handler/controller 交互用 `emit` 事件；
- 不排期。

### 2.5 P1 标准库/容器

- Array：✅ push/pop/shift/unshift/slice/concat/join/indexOf/includes/clear/sort/reverse；
- Map：✅ keys/values/clear；`entries` 待做（需要 pair 类型设计）；
- String：✅ 字节方法 + `replace`；UTF-8 码点长度/`charAt` 语义待做；
- `Json.stringify(obj)`：复用 Struct 元数据；v1 先支持 struct/event + 标量/String/嵌套 ref，容器字段需给容器补元素类型元数据；
- Host 增补：文件追加、日志级别、网络客户端；
- 验收：每个方法有 .we 用例；容器 oid/写权限检查保持；RC 无泄漏。

### 2.6 P2 运行时/内存/性能

- **Cache 容量上限/淘汰**（审计 B1）：env 配置最大条数/字节，简单淘汰策略（LRU 或分片内 FIFO），避免长跑内存单调增长；
- **TTL 默认关闭时的环泄漏**：手动清理 API（`Model.cleanup`）已按用户要求去掉；环回收目前仍只依赖 `WELL_MODEL_TTL_MS`（默认关闭）；环/跨 oid/static 约束已写入 IMPLEMENTATION §3.3，后续如需要再设计手动/独立清理机制；
- **调度器 per-worker 锁**（🔒 结构性）：去掉单把 `g_sched_mutex`，提升并发吞吐（当前 4 客户端 ~41–60k vs raw 67–86k）；
- **阻塞 I/O 让渡/超时**：File/MySQL 同步调用会占用 worker，后续考虑 offload 线程池或 async；
- **对象注册表锁优化**：`well_new`/`well_release` 每次 oid 分片加锁；
- HTTP/WS 生产化：TLS、chunked、pipelining、背压、同端口 Upgrade、连接数上限/503；
- MySQL：TLS、prepared statement、事务 API、caching_sha2、事件化/异步；
- 热更新：模块版本/重新加载/旧订阅注销；
- 内存池：容器/String 变长 buffer、generation/dead、压力测试；
- 泛型/接口/FFI（远期）。

### 2.7 P2 工程化

- **压测 + 一键回归入库**：C 客户端、raw C 基线、`GET /ping` 服务、`verify` 脚本（build + 86 用例 + C 测试 + 压测）；
- **POSIX CI**：本机只有 Windows tcc 验证；Linux 构建/测试需容器化；
- ASan/LSan/fuzz/并发 stress、MSVC/跨平台；
- 运行时指标：worker 利用率、steal 次数、队列长度、handler 耗时（可选 env 开关）。

- 避免语言核心与具体数据库绑定。

### 3.1 多 Model / 多 Store 目标（未来）

```text
MysqlModel -> Cache
MysqlModel -> MysqlStore

FileModel -> Cache
FileModel -> FileStore
```

- `Store.get`/`Store.set` 是纯后端操作，不自动读写 Cache；

- Cache 全局共享，key 为 `(type_id, oid)`，不记录来源；
- 多个 Model 可加载同一 key，最后一次 `Cache.set` 覆盖；数据一致性由用户负责。

- mapping 必须在第一次 Store 使用前注册并校验；
- 业务键主键、oid 唯一索引由用户建表负责。

## 4. 关键约定（当前运行时）

### 4.1 oid / IdUtil

- oid 固定 `long`，由 `IdUtil.getId()` 生成（serverId + timestamp + sequence）；
- `WELL_SERVER_ID` 0..1023；同 oid FIFO、单 runner，异 oid 并行；
- oid 不是 MySQL 主键；业务键才是 DB 主键。

### 4.2 Cache / Model / Store

- Cache 全局共享，key `(type_id, oid)`，不记录对象来源；多个 Model/Store 的 key 冲突由用户负责；
- 当前运行时仍是**单全局 Model + 单 Store**；
- `Model.get` 先查 Cache，miss 时 Store.select → Cache.set；`Model.peek` 只查 Cache；
- `Model.set` 先 Store.upsert 再 Cache.set；`Model.remove` 先 Store.delete 再 Cache.remove；
- MemoryStore 纯后端，不查 Cache；**Cache 目前无容量上限/淘汰**（§2.6）；

### 4.3 GC / TTL / 内存

- RC 保留；对象 rc0 后进入固定大小对象池（env 缓存、1s 节流 sweep）；
- oid 维护 `exec_ref`（handler/event 持有 +1、释放 -1）与 `last_active`（只由 Cache.get/set 更新）；
- oid 过期条件：TTL 到期 + exec_ref == 0 + 调度器空闲；
- 满足后 registry 中该 oid 全部对象强制清理，Cache 行 discard，Store 字节保留；
- 环形数据由 oid 过期兜底；运行时不做环检查；
- 局部作用域释放：loop/block/function/return/break/continue；
- 帧日志：`WellCtx` 内联 16 ref + 4 pin，溢出才堆分配；
- 池：`WELL_POOL_TTL_MS` 到期真正 free；`WELL_POOL_MAX_MB` 上限。

### 4.4 事件 oid / 订阅

- event `oid` 必须非 0；`new Event(0)` / emit 前 oid=0 时用 `IdUtil` 自动生成；
- 所有 event 统一进入 oid 队列调度；
- 订阅支持 `on/once/off(Handler[, channel])` 与显式 `(EventType, Handler[, channel])`；二参时首参是 handler 名按 `(Handler, channel)` 解释；
- `emit` 异步派发；在 run loop 之前 `off` 会取消尚未派发事件的投递。

### 4.5 元数据 / 序列化 / JSON

- 每个 struct/event 生成 `WellTypeDesc`；行级二进制格式 `WLS1`；
- JSON：仅 `Json.parse(Type, String)`；`stringify` 待做；ref 编码为 `type_id + oid`，解码用 resolver；嵌套容器暂不支持；
- namespace/static 编译期解析：`N.f(...)` → `static N__f`，`S.f`/`S.m()` → C 全局变量/静态函数；零运行时开销；static 字段并发写由使用者负责。

### 4.6 网络 / MySQL / 平台限制

- HTTP：多连接 + keep-alive、同步响应快速路径、连接级路由缓存；无 TLS/chunked/pipelining/连接数上限；
- WS：单连接模型、text frame、独立端口、无背压；
- MySQL：native auth、COM_QUERY、连接池；无 TLS/prepared/事务 API；
- 最终部署目标 Linux；Windows 使用 TCC 验证；**POSIX 路径本机尚未验证**；
- Windows 条件变量为原生 `CONDITION_VARIABLE`（动态加载，Vista+）。

### 4.7 语言检查边界（当前）

- 返回类型、全路径 return、类型名、重复声明、break/continue 位置、容器字面量实参均有明确编译错误；
- 整数除零/溢出未检查（除零会崩溃）；
- 无 switch、异常/Result、泛型、接口、类型转换、defer、字符串插值。

10. **标准库**：Json.stringify、Map.entries、UTF-8 码点、Host 增补；
11. **运行时/工程化**：Cache 上限、TTL 默认策略、per-worker 锁（🔒）、I/O 让渡、HTTP/WS 生产化、MySQL 高级能力、热更新、bench/verify 入库、POSIX CI；
12. **用户侧 Store/Model**（暂缓）：MysqlModel/MysqlStore/FileModel/FileStore/Mapping/业务键；
13. **高级语言能力**：泛型/接口/FFI。

> 明确不做：`invoke`（同 oid 同步调用，D-21 已从语言删除；计算用 `func`，跨 handler 用 `emit`）。

> 一句话：语言运行时、GC、Store 基础稳定；当前重点是**错误处理与继承体系**，之后补语法完整性与标准库；性能方面剩余的大头是 Cache 上限、调度器 per-worker 锁（🔒）与 HTTP/WS 生产化。
